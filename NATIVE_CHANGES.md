## Proposals (not built)
- **Live Activity / Dynamic Island: "next prayer".** None exists today (`Attributes.swift`/`Module.swift` are stubs the plugin requires). Proposal: start a Live Activity from the app when the next prayer is within a chosen window (e.g. 30 min, user setting) showing Lock Screen: prayer name, `Text(date, style: .timer)` hero in serif tabular numerals, apricot progress rule (ProgressView(timerInterval:)), city; Dynamic Island compact: moon.stars glyph + timer, expanded: name + timer + time, minimal: glyph. Same tokens (DTSky ramp background, DTNight text, apricot only on rule/state). It ends at the prayer time (`staleDate` = prayer time) so no push is needed. Requires: `NSSupportsLiveActivities` = YES in the app Info.plist (app.json `ios.infoPlist`), real implementations of `Module.swift` start/update/end (currently stubs returning ""/false, which must be changed - that touches the native bridge), `ActivityAttributes.ContentState` fields, a Widget `ActivityConfiguration` in the widget target, and a JS trigger near `useNotificationScheduler`. Risk: touches the bridge contract this brief forbids changing, so it is deferred to an explicit go-ahead; cannot be compile-verified on this machine.
